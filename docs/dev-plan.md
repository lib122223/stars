# 开发计划：Echo of Photons

## 文档目的

本文档用于定义 Echo of Photons 当前阶段的开发计划。
它的目标不是重写产品需求，而是把已经在 `requirements.md` 和 `tech-spec.md` 中确认的产品与技术结论，继续整理成可执行的分阶段交付顺序。

与前一版相比，当前计划更强调按用户真实看到的功能模块推进，而不是按抽象能力建设顺序推进。后续所有“最小任务 1 / 2 / 3”的拆分，都应继续从本文件往下切。

---

## 阶段 1：现有主链路稳定化

### 目标

先把当前已经存在的首页、星图、详情、工具页和线上部署链路稳定住，避免后续新功能建立在摇晃的底座上。

### 任务清单

- 回归首页推荐、搜索、目标跳转、详情承接、工具页访问
- 稳定 `DATABASE_URL`、API 调用和线上环境表现
- 回归 `GET /api/recommendations`
- 回归 `GET /api/sky-map/resolve`
- 回归 `GET /api/objects/[slug]`
- 回归 `GET /api/tools/observation-summary`
- 保持域名、HTTPS、定位权限链路可继续使用

### 验证标准

- 首页、星图、详情、工具页都能稳定打开
- 搜索、点击目标、详情承接不再随机失败
- 本地与线上访问主链路一致
- 构建可通过，线上不再有明显断链

---

## 阶段 2：首页入口重构

### 目标

把首页变成真正的“今晚行动入口页”，而不是泛信息页。

### 任务清单

- 收敛首页第一屏动作为 4 个入口：
  - 开始看一下
  - 看 2D 星图
  - 查看观测条件
  - 换一个目标
- 明确视觉权重：
  - 最强：开始看一下
  - 第二层：看 2D 星图、查看观测条件
  - 最轻：换一个目标
- 收敛首页轻信息结构：
  - 今晚观测条件
  - 最佳观察时间
  - 附近更优区域提示
- 收清首页到后续页面的承接语义：
  - 首页到观察模式
  - 首页到 2D 星图模式
  - 首页到工具页
- “换一个目标”先保持轻操作，不做重页面

### 验证标准

- 新用户打开首页后能立刻知道第一步做什么
- 首页不是内容堆叠页
- 首页信息服务于动作，不喧宾夺主
- 首页与后续页面的承接语义清楚

---

## 阶段 3：2D 星图模式收口

### 目标

把当前星图模式正式收口为“参考模式”，稳定其搜索、点击、标签和详情承接能力。

### 任务清单

- 明确 2D 星图模式在产品中的职责：查位置、看结构、做平面参考
- 稳定搜索、`target`、`source`、BottomDrawer、详情承接链路
- 继续优化对象可见性、标签层级与点击反馈
- 在 2D 星图模式下先解决移动端“点星星费劲”的问题
- 保持 2D 星图模式不承担观察模式的沉浸式职责

### 验证标准

- 2D 星图模式作为参考模式的角色稳定
- 搜索和点击链路顺畅
- 移动端目标命中体验明显改善
- 不再把 2D 星图模式当作观察模式半成品使用

---

## 阶段 4：观察模式入口与模式边界

### 目标

先把观察模式从产品结构上独立出来，建立它与 2D 星图模式的边界。

### 任务清单

- 区分 2D 星图模式与观察模式的状态与入口
- 让首页“开始看一下”正式承接到观察模式语义
- 为观察模式建立独立 `mode state / view state`
- 实现“当前天空优先、推荐目标轻线索带入”的入口规则
- 保持此阶段不急着上完整朝向驱动与时间滑动

### 验证标准

- 观察模式在结构上已是独立模式
- 首页到观察模式的承接成立
- 2D 星图模式与观察模式不再混作一套状态
- 推荐目标可以作为轻任务进入观察模式

---

## 阶段 5：观察模式视图模型重构

### 目标

把观察模式从“像拖动 2D 星图”重构为“手机就是看天窗口”的正确模型。

### 任务清单

- 重构视图模型为：天空固定、视窗移动
- 让屏幕中心代表当前正对的天空区域
- 让设备朝向改变视窗，而不是改变天空本体
- 解决“星星被甩到屏幕两边”的错误感受
- 保持现有 `target` / `source` / 搜索 / 详情承接不被破坏

### 验证标准

- 用户转动手机时感受到的是视角变化，不是整张图乱跑
- 中心区域和现实朝向的对应关系稳定
- 观察模式与 2D 星图模式在体验上已经明显分开

---

## 阶段 6：观察模式目标引导与确认层

### 目标

让用户在观察模式中更容易找到目标、点中目标，并在点中后先进入确认层，而不是直接跳详情页。

### 任务清单

- 实现轻引导三段状态：
  - 未接近
  - 接近
  - 确认
- 实现动态点击热区
- 接入中等聚焦态：
  - 目标名
  - 一句短状态
  - 查看详情
  - 缩回天空
- 保持引导轻量，不使用大箭头、强导航或持续闪烁框
- 保持详情页作为后续承接，而不是直接抢走观察主舞台

### 验证标准

- 用户更容易找到并点中目标
- 观察模式不会因为强引导而失真
- 点中后先确认，再决定是否看详情
- “缩回天空”动作自然存在

---

## 阶段 7：观察模式时间滑动与星座辅助

### 目标

让观察模式具备“今晚不同时间下天空如何变化”的真实观测能力。

### 任务清单

- 接入今晚时间线
- 将时间滑动做成半隐藏入口
- 实现“真实模拟为主，产品辅助为辅”的时间变化
- 让背景亮度、星体可见性、目标状态随时间变化
- 加入最佳观察时间的轻强调
- 让星座辅助按渐进逻辑工作：
  - 关键亮星先明显
  - 结构感再增强
  - 弱连线最后出现
- 将星座辅助开关放入轻菜单

### 验证标准

- 时间滑动不会破坏观察模式主舞台
- 用户能理解“什么时候更适合看”
- 星座辅助不会变成一层死板教学覆盖层
- 首页的最佳时间判断与观察模式内的变化逻辑一致

---

## 阶段 8：工具页升级

### 目标

把工具页从说明页升级为真正的观测判断页。

### 任务清单

- 固定工具页第一版的 4 个模块：
  - 今晚观测总结论
  - 影响因素
  - 附近更优区域提示
  - 近期可关注天象
- 组织今晚观测结论的表达结构
- 组织影响因素结构：
  - 云量
  - 月光干扰
  - 天空清晰度
  - 观测窗口
- 实现“附近更优区域提示”的结果结构与表现
- 保持首页只展示轻提示，工具页展示完整判断

### 验证标准

- 工具页明显像工具，不像说明页
- 用户能从工具页得出“今晚看不看、要不要换地方”的结论
- 更优区域提示是一个可行动结果，而不是排行榜

---

## 阶段 9：未来天象日历

### 目标

建立长期计划入口，第一版聚焦未来一年流星雨预测。

### 任务清单

- 在工具页加入轻量的“近期天象预告”入口
- 建立独立未来天象日历页
- 实现未来一年流星雨总览
- 页面结构采用：
  - 全年时间轴
  - 按月事件列表
- 为每场流星雨提供统一字段：
  - 名称
  - 活跃期
  - 峰值夜晚
  - 强度
  - 推荐观测时段
  - 观测提醒
  - 理想观测地类型
  - 区域级更优建议

### 验证标准

- 日历页是一页真正可计划的工具页
- 计划型为主、百科型为辅的口径成立
- 不会把流星雨错误做成本地天气事件
- 工具页与日历页之间入口自然

---

## 阶段 10：观测参考图内容层

### 目标

引入“肉眼参考 + 摄影参考”的参考图体系，增强可信度与观测预期管理。

### 任务清单

- 在详情页接入肉眼参考图
- 在详情页接入摄影参考图
- 在天象事件页接入事件参考图
- 为参考图补齐基础元数据：
  - 摄影师
  - 拍摄地
  - 拍摄时间
  - 设备说明
  - 授权信息
- 保持默认先展示肉眼参考，再展示摄影参考

### 验证标准

- 用户不会被大片直接误导
- 参考图先回答“我现在大概能看到什么”
- 摄影参考图补充理想观感，而不替代真实观感

---

## 阶段 11：后端数据层扩展

### 目标

让后端从轻内容接口层升级为能稳定支撑事件、区域比较和参考图内容的观测数据层。

### 任务清单

- 建立天象事件数据层
- 建立流星雨数据层
- 建立附近更优区域比较数据层
- 建立观测参考图内容层
- 为这些能力补齐 API 与数据结构
- 保持现有 Next.js + TypeScript + PostgreSQL 技术主线不变

### 验证标准

- 工具页、天象日历页、详情页不再依赖散乱静态拼装
- 事件、区域、媒体三类数据有稳定结构
- 后端扩展是服务前面功能块，而不是脱离产品主线自转

---

## 阶段 12：用户计划层预研

### 目标

为持续使用做准备，但不提前把产品变成重账号系统。

### 任务清单

- 预研收藏能力
- 预研观测计划能力
- 预研观测记录能力
- 预研设备配置能力
- 判断哪一类最适合作为第一批用户层能力落地

### 验证标准

- 能清楚判断用户层下一步优先级
- 不会因为过早建设用户系统而拖慢主产品主线

---

## 回归检查清单

每个阶段结束后，至少检查以下链路：

- 首页 -> 开始看一下 -> 观察模式
- 首页 -> 看 2D 星图 -> 搜索 / target 跳转
- 首页 -> 查看观测条件 -> 工具页
- 观察模式 -> 点击对象 -> 中等聚焦态 -> 查看详情
- 详情页 -> 返回天空 / related 承接
- 工具页 -> 近期天象预告 -> 天象日历页
- 域名 HTTPS 环境下的定位与权限行为
- `GET /api/recommendations`
- `GET /api/sky-map/resolve`
- `GET /api/objects/[slug]`
- `GET /api/tools/observation-summary`

---

## 推荐执行顺序总览

1. 现有主链路稳定化
2. 首页入口重构
3. 2D 星图模式收口
4. 观察模式入口与模式边界
5. 观察模式视图模型重构
6. 观察模式目标引导与确认层
7. 观察模式时间滑动与星座辅助
8. 工具页升级
9. 未来天象日历
10. 观测参考图内容层
11. 后端数据层扩展
12. 用户计划层预研

这个顺序对应我们昨天已经确认的产品主次：先把入口和核心体验做对，再把工具、计划和内容做厚。
