# 设计规范：Echo of Photons

## 文档目的

本文件用于定义 Echo of Photons 第一阶段的 UI 与交互设计方向。
它的作用是在进入实现前，对产品气质、页面职责、视觉语言和交互优先级进行统一。

第一阶段不追求一次性做出完整穷尽的设计系统。
当前目标是先锁定高层设计原则，以及各核心页面的主方向，用来指导后续 UI 实现与设计审查。

---

## 1. 设计原则

### 1.1 核心方向

Echo of Photons 第一阶段采用混合设计原则：

**工具结构 + 探索气质**

这意味着：
- 交互结构要像工具型产品一样清楚、可用
- 情绪气质要保留好奇心、夜空氛围和探索感
- UI 既不能变成冷硬的纯工具界面，也不能变成只有氛围没有结构的展示页

### 1.2 产品感觉

我们希望用户感受到的是：
- 足够清楚，能快速开始
- 足够平静，不显得嘈杂
- 足够有趣，愿意继续探索
- 足够有夜空关联感，而不是一般科技产品气质

### 1.3 需要避免的极端

第一阶段要避免滑向这两个极端：

- 冷硬、强操作感、纯天文工具界面
- 很沉浸、很氛围化，但结构松散、产品性差的探索页面

---

## 2. 配色方向

### 2.1 主方向

第一阶段配色采用：

**深夜底色 + 星光暖色点缀**

这意味着：
- 深色背景承载夜空氛围
- 暖色强调只用在推荐、主动作、关键对象和探索入口上
- 视觉系统不能塌成泛用的蓝黑科技风

### 2.2 颜色角色原则

颜色层级遵循以下原则：

- 深背景承担沉浸感与聚焦感
- 暖色强调承担方向感与好奇心
- 强调色使用要克制，不能为了装饰而装饰
- 推荐动作与关键探索点的强调强度，应高于一般界面外壳和普通控件

---

## 3. 页面级设计方向

### 3.1 首页

首页应被定义为：

**今日引导入口页**

它应该：
- 降低启动成本
- 快速回答“今天可以先看什么”
- 把用户顺势带进星图流程
- 保留探索感，但不发展成开放式内容广场

首页不应像：
- 后台式操作面板
- 完全自由探索中心
- 重内容流编辑页

### 3.2 星图页

星图页是第一阶段的核心交互页。
它的外围 UI 应采用：

**沉浸外壳**

但这种沉浸外壳必须服务认星，而不是盖住认星。
也就是说：
- 页面要像进入夜空一样
- 星图本体必须始终是主舞台
- 外壳不能压住对象识别、点击、详情承接
- 氛围可以有，但不能以牺牲交互清晰度为代价

### 3.3 详情页

详情页应围绕：

**探索卡**

来设计。

这意味着：
- 它不能只停在事实解释
- 它要用知识继续承接探索动力
- 卡片要明确回答：
  - 它是什么
  - 为什么值得看
  - 下一步还能看什么

详情页不应像：
- 死板百科词条
- 干巴巴的技术参数面板
- 与主流程脱节的纯内容文章页

### 3.4 工具页

工具页应被定义为：

**轻辅助页**

它应该：
- 提供轻量观测摘要
- 服务主产品闭环，而不是与它争主场
- 保持比首页和星图页更低的视觉重量

工具页不应发展成：
- 重专业控制中心
- 高密度参数面板
- 与星图页并列的第二主战场

---

## 4. 交互优先级

### 4.1 页面优先级划分

第一阶段的页面交互划分为：

- 首页：内容优先，轻交互
- 星图页：重交互核心
- 详情页：内容优先，只承接局部交互
- 工具页：内容优先，轻交互

### 4.2 交互重心

第一阶段只有星图页是明确的高交互核心页。
首页和工具页不能长成同样重的操作界面。

### 4.3 承接节奏

我们希望的交互节奏是：

1. 首页降低启动成本
2. 用户进入星图
3. 星图支持识别
4. 点击对象进入详情页
5. 详情页继续承接探索动力

这种节奏必须在布局和交互设计里都能被看出来。

---

## 5. 字体层级

### 5.1 不同页面的标题强调

第一阶段不能所有页面都用同一种标题强度。
标题强度应跟页面职责走：

- 首页标题：入口级强调
- 星图页标题：场景级强调
- 详情页标题：对象级强调
- 工具页标题：标准页面级标题

这意味着首页和星图页可以承担略强一点的视觉牵引，
而工具页应更克制、更功能性。

### 5.2 正文原则

正文文字应优先保证产品可读性，而不是内容编辑感。
它应该读起来平静、清楚、信息性强，而不是诗化或过度内容化。

---

## 6. 组件表达规则

### 6.1 按钮

按钮整体方向为：

**产品式按钮 + 轻探索语气**

这意味着：
- 按钮首先必须清楚可点
- 关键动作可以吸收一点气质，但不能失去点击清晰度
- 首页主按钮可以略带邀请感
- 星图页工具按钮应收住，保持服务感
- 详情页探索动作可以略带更强的探索延续感
- 工具页动作保持稳定、次级

### 6.2 卡片

卡片整体方向为：

**产品结构 + 探索层次**

这意味着不同页面的卡片可以承担不同情绪重量：

- 首页推荐卡：最强的行动邀请
- 星图承接卡：克制的过渡支持
- 详情页探索卡：最强的好奇心承接
- 工具摘要卡：更轻、更次级

### 6.3 标签

标签整体方向保持：

**低权重、产品式表达**

标签只用于帮助用户扫描对象类型、场景分类和推荐分组。
它们不应在视觉上与标题、理由、动作按钮争主角。

### 6.4 首页推荐结构

首页推荐区应采用清楚的“主次分层”：

- 一个主推荐卡
- 一个辅推荐轻入口
- 一层贴近主推荐、但不与之争主角的条件信息

主推荐卡需要承载：
- 今晚看什么
- 一句短理由
- 一个通向星图流程的主动作
- 一个通向对象详情的次动作

辅推荐不应表现得像第二张完整大卡。
它应作为同主题补充，给用户一个更轻、更具体的抓手。

### 6.5 首页主推荐卡风格

首页主推荐卡应采用：

**轻星空风格，而不是重沉浸式**

这意味着：
- 卡片可以使用深夜底色、暖高光、柔和微光和稀疏星点装饰
- 卡片应与夜空发生联系，但不能像海报，也不能像缩小版星图
- 卡片可以允许极轻动态，例如慢呼吸、弱闪烁
- 氛围感不能影响标题可读性和动作清晰度
- 首页负责邀请进入夜空，完整沉浸感应留给星图页承担

### 6.6 星图页表层规则

星图页必须让星图本体成为绝对视觉与交互中心。
外围 UI 要存在，但必须收住：

- 顶部只能是很轻的页头，而不是重标题带
- 底部承接区应是轻承接面，而不是大型控制面板
- 浮动工具应轻量，始终从属于星图本体
- 页面要有产品归属感，但不能被产品外壳过度包裹

### 6.7 详情页回流规则

对象详情页不能被设计成一个内容终点页。
它的主要延续动作应把用户带回探索中。

这意味着：
- “返回继续探索”应是主动作
- 文案要体现“继续看”的感觉，而不是冷冰冰的返回动作
- 如果技术允许，回流时应尽量恢复最近一次星图上下文，而不是丢回默认状态

## 7. 页面第一眼注意顺序

### 7.1 首页

首页第一眼应该让用户注意到：

1. 今晚看什么
2. 夜空探索的感觉
3. 下一步动作入口

也就是说，CTA 按钮应该像兴趣形成后的自然下一步，
而不是首页第一眼最强信号。

### 7.2 星图页

星图页第一眼应该让用户注意到：

1. 夜空本体
2. 这是一个带着识别目标进入的页面
3. 局部控件与承接 UI

星图本体始终是主舞台。
控件、叠层和界面外壳都应退后。

### 7.3 详情页

详情页第一眼应该让用户注意到：

1. 这是什么对象
2. 为什么值得看
3. 接下来继续探索什么

页面不应由次级元数据或导航机制抢第一注意力。

### 7.4 工具页

工具页第一眼应该让用户注意到：

1. 今晚大体适不适合观测
2. 这个页面能帮什么
3. 次级设置与后续入口

工具页应先让人放心，再提供帮助。
它不应像一个重控制台。

## 8. 关键页面布局优先级

### 8.1 首页第一屏

首页第一屏的布局优先级应为：

1. 主推荐卡作为最大视觉块
2. 贴近主推荐的轻条件说明
3. 同主题的辅推荐一行式轻入口

条件说明不应长成天气面板。
它只服务推荐，不抢首页主职责。

条件层再细分为两部分：
- 依据层：简洁客观描述，例如天空晴朗程度、月光影响
- 行动层：把这些条件翻译成“今晚怎么开始更合适”的建议

### 8.2 星图页第一屏

星图页第一屏结构应为：

- 星图本体作为主舞台
- 很轻的顶部页头
- 一个轻底部承接区
- 大约 3 个轻量浮动辅助工具

在用户点对象之前，底部承接区应显示：
- 今晚引导用户去找什么
- 一句短理由

在用户点对象之后，同一个区域应立即切换为：
- 对象摘要
- 详情入口

这个承接区应负责“承接与转交”，而不是长成持续堆叠的大卡区或重工具 dock。

### 8.3 详情页延续方式

详情页应先解释，再延续。
它的主动作必须明确鼓励用户回到夜空继续探索，而不是把体验终止在内容消费上。

---

## 9. 第一阶段范围说明

本设计规范当前锁定的是大方向与页面级原则。
以下更细的设计系统工作：
- 具体字号比例
- 组件间距系统
- 明确 token 数值
- 更细的交互状态
- 逐页的高保真界面说明

可以在后续更接近实现时继续扩展。
