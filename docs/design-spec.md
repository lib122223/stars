# 设计规范：Echo of Photons

## 文档目的

本文件用于定义 Echo of Photons 第一阶段的 UI 与交互设计方向。
它的作用是在进入实现前，对产品气质、页面职责、视觉语言和交互优先级进行统一。

第一阶段不追求一次性做出完整穷尽的设计系统。
当前目标是先锁定高层设计原则，以及各核心页面的主方向，用来指导后续 UI 实现与设计审查。

---

## 1. 设计原则

### 1.1 核心方向

Echo of Photons 第一阶段采用混合设计原则：

**工具结构 + 探索气质**

这意味着：
- 交互结构要像工具型产品一样清楚、可用
- 情绪气质要保留好奇心、夜空氛围和探索感
- UI 既不能变成冷硬的纯工具界面，也不能变成只有氛围没有结构的展示页

### 1.2 产品感觉

我们希望用户感受到的是：
- 足够清楚，能快速开始
- 足够平静，不显得嘈杂
- 足够有趣，愿意继续探索
- 足够有夜空关联感，而不是一般科技产品气质

### 1.3 需要避免的极端

第一阶段要避免滑向这两个极端：

- 冷硬、强操作感、纯天文工具界面
- 很沉浸、很氛围化，但结构松散、产品性差的探索页面

---

## 2. 配色方向

### 2.1 主方向

第一阶段配色采用：

**深夜底色 + 星光暖色点缀**

这意味着：
- 深色背景承载夜空氛围
- 暖色强调只用在推荐、主动作、关键对象和探索入口上
- 视觉系统不能塌成泛用的蓝黑科技风

### 2.2 颜色角色原则

颜色层级遵循以下原则：

- 深背景承担沉浸感与聚焦感
- 暖色强调承担方向感与好奇心
- 强调色使用要克制，不能为了装饰而装饰
- 推荐动作与关键探索点的强调强度，应高于一般界面外壳和普通控件

---

## 3. 页面级设计方向

### 3.1 首页

首页应被定义为：

**今日引导入口页**

它应该：
- 降低启动成本
- 快速回答“今天可以先看什么”
- 把用户顺势带进星图流程
- 保留探索感，但不发展成开放式内容广场

首页不应像：
- 后台式操作面板
- 完全自由探索中心
- 重内容流编辑页

### 3.2 星图页

星图页是第一阶段的核心交互页。
它的外围 UI 应采用：

**沉浸外壳**

但这种沉浸外壳必须服务认星，而不是盖住认星。
也就是说：
- 页面要像进入夜空一样
- 星图本体必须始终是主舞台
- 外壳不能压住对象识别、点击、详情承接
- 氛围可以有，但不能以牺牲交互清晰度为代价

### 3.3 详情页

详情页应围绕：

**探索卡**

来设计。

这意味着：
- 它不能只停在事实解释
- 它要用知识继续承接探索动力
- 卡片要明确回答：
  - 它是什么
  - 为什么值得看
  - 下一步还能看什么

详情页不应像：
- 死板百科词条
- 干巴巴的技术参数面板
- 与主流程脱节的纯内容文章页

### 3.4 工具页

工具页应被定义为：

**轻辅助页**

它应该：
- 提供轻量观测摘要
- 服务主产品闭环，而不是与它争主场
- 保持比首页和星图页更低的视觉重量

工具页不应发展成：
- 重专业控制中心
- 高密度参数面板
- 与星图页并列的第二主战场

---

## 4. 交互优先级

### 4.1 页面优先级划分

第一阶段的页面交互划分为：

- 首页：内容优先，轻交互
- 星图页：重交互核心
- 详情页：内容优先，只承接局部交互
- 工具页：内容优先，轻交互

### 4.2 交互重心

第一阶段只有星图页是明确的高交互核心页。
首页和工具页不能长成同样重的操作界面。

### 4.3 承接节奏

我们希望的交互节奏是：

1. 首页降低启动成本
2. 用户进入星图
3. 星图支持识别
4. 点击对象进入详情页
5. 详情页继续承接探索动力

这种节奏必须在布局和交互设计里都能被看出来。

---

## 5. 字体层级

### 5.1 不同页面的标题强调

第一阶段不能所有页面都用同一种标题强度。
标题强度应跟页面职责走：

- 首页标题：入口级强调
- 星图页标题：场景级强调
- 详情页标题：对象级强调
- 工具页标题：标准页面级标题

这意味着首页和星图页可以承担略强一点的视觉牵引，
而工具页应更克制、更功能性。

### 5.2 正文原则

正文文字应优先保证产品可读性，而不是内容编辑感。
它应该读起来平静、清楚、信息性强，而不是诗化或过度内容化。

---

## 6. 组件表达规则

### 6.1 按钮

按钮整体方向为：

**产品式按钮 + 轻探索语气**

这意味着：
- 按钮首先必须清楚可点
- 关键动作可以吸收一点气质，但不能失去点击清晰度
- 首页主按钮可以略带邀请感
- 星图页工具按钮应收住，保持服务感
- 详情页探索动作可以略带更强的探索延续感
- 工具页动作保持稳定、次级

### 6.2 卡片

卡片整体方向为：

**产品结构 + 探索层次**

这意味着不同页面的卡片可以承担不同情绪重量：

- 首页推荐卡：最强的行动邀请
- 星图承接卡：克制的过渡支持
- 详情页探索卡：最强的好奇心承接
- 工具摘要卡：更轻、更次级

### 6.3 标签

标签整体方向保持：

**低权重、产品式表达**

标签只用于帮助用户扫描对象类型、场景分类和推荐分组。
它们不应在视觉上与标题、理由、动作按钮争主角。

### 6.4 首页推荐结构

首页推荐区应采用清楚的“主次分层”：

- 一个主推荐卡
- 一个辅推荐轻入口
- 一层贴近主推荐、但不与之争主角的条件信息

主推荐卡需要承载：
- 今晚看什么
- 一句短理由
- 一个通向星图流程的主动作
- 一个通向对象详情的次动作

辅推荐不应表现得像第二张完整大卡。
它应作为同主题补充，给用户一个更轻、更具体的抓手。

### 6.5 首页主推荐卡风格

首页主推荐卡应采用：

**轻星空风格，而不是重沉浸式**

这意味着：
- 卡片可以使用深夜底色、暖高光、柔和微光和稀疏星点装饰
- 卡片应与夜空发生联系，但不能像海报，也不能像缩小版星图
- 卡片可以允许极轻动态，例如慢呼吸、弱闪烁
- 氛围感不能影响标题可读性和动作清晰度
- 首页负责邀请进入夜空，完整沉浸感应留给星图页承担

### 6.6 星图页表层规则

星图页必须让星图本体成为绝对视觉与交互中心。
外围 UI 要存在，但必须收住：

- 顶部只能是很轻的页头，而不是重标题带
- 底部承接区应是轻承接面，而不是大型控制面板
- 浮动工具应轻量，始终从属于星图本体
- 页面要有产品归属感，但不能被产品外壳过度包裹

### 6.7 详情页回流规则

对象详情页不能被设计成一个内容终点页。
它的主要延续动作应把用户带回探索中。

这意味着：
- “返回继续探索”应是主动作
- 文案要体现“继续看”的感觉，而不是冷冰冰的返回动作
- 如果技术允许，回流时应尽量恢复最近一次星图上下文，而不是丢回默认状态

## 7. 页面第一眼注意顺序

### 7.1 首页

首页第一眼应该让用户注意到：

1. 今晚看什么
2. 夜空探索的感觉
3. 下一步动作入口

也就是说，CTA 按钮应该像兴趣形成后的自然下一步，
而不是首页第一眼最强信号。

### 7.2 星图页

星图页第一眼应该让用户注意到：

1. 夜空本体
2. 这是一个带着识别目标进入的页面
3. 局部控件与承接 UI

星图本体始终是主舞台。
控件、叠层和界面外壳都应退后。

### 7.3 详情页

详情页第一眼应该让用户注意到：

1. 这是什么对象
2. 为什么值得看
3. 接下来继续探索什么

页面不应由次级元数据或导航机制抢第一注意力。

### 7.4 工具页

工具页第一眼应该让用户注意到：

1. 今晚大体适不适合观测
2. 这个页面能帮什么
3. 次级设置与后续入口

工具页应先让人放心，再提供帮助。
它不应像一个重控制台。

## 8. 关键页面布局优先级

### 8.1 首页第一屏

首页第一屏的布局优先级应为：

1. 主推荐卡作为最大视觉块
2. 贴近主推荐的轻条件说明
3. 同主题的辅推荐一行式轻入口

条件说明不应长成天气面板。
它只服务推荐，不抢首页主职责。

条件层再细分为两部分：
- 依据层：简洁客观描述，例如天空晴朗程度、月光影响
- 行动层：把这些条件翻译成“今晚怎么开始更合适”的建议

### 8.2 星图页第一屏

星图页第一屏结构应为：

- 星图本体作为主舞台
- 很轻的顶部页头
- 一个轻底部承接区
- 大约 3 个轻量浮动辅助工具

在用户点对象之前，底部承接区应显示：
- 今晚引导用户去找什么
- 一句短理由

在用户点对象之后，同一个区域应立即切换为：
- 对象摘要
- 详情入口

这个承接区应负责“承接与转交”，而不是长成持续堆叠的大卡区或重工具 dock。

### 8.3 详情页延续方式

详情页应先解释，再延续。
它的主动作必须明确鼓励用户回到夜空继续探索，而不是把体验终止在内容消费上。

## 9. 第一阶段范围说明

本设计规范当前锁定的是大方向与页面级原则。
以下更细的设计系统工作：
- 具体字号比例

- 明确 token 数值
- 更细的交互状态
- 逐页的高保真界面说明

可以在后续更接近实现时继续扩展。

## 10. V2 StarCanvas 视觉规范

### 10.1 设计定位

V2 当前星图主舞台由 StarCanvas 承担。它不是专业巡天图，也不是单纯装饰背景，而是服务新手认星的产品化夜空界面。

StarCanvas 的视觉目标是：
- 第一眼像夜空，而不是调试画布
- 主要对象可读、可点、可继续探索
- 背景星点提供氛围，不制造专业星图密度
- 目标引导清楚，但不变成强教程遮罩

### 10.2 星点层级

星点应分为三层：
1. 背景星点：数量适中、亮度低，只提供夜空氛围
2. 可识别对象：亮度和尺寸明显高于背景星点，支持点击
3. 当前推荐目标：在可识别对象基础上增加暖色光晕或外圈，但不遮挡标签

行星、亮星和星座关键点可以有不同色温，但整体应保持深夜底色与暖色强调的产品一致性。

### 10.3 标签层级

标签默认使用中文主标签。英文名可在后续作为小字号副标签，但不应成为主识别信息。

标签规则：
- 主要可点击对象显示中文标签
- 标签不应覆盖星点或点击热区
- 标签数量保持克制，优先显示当前 MVP 对象
- 背景星点不显示标签
- 未入库或不能承接详情的对象，不应表现得像完整可点击对象

### 10.4 星座线与区域

星座线用于帮助新手建立形状记忆，视觉权重应低于可点击对象和当前目标。

星座对象可以使用区域热区承接点击，但热区必须贴近真实可见星座结构，不能覆盖过大片空白区域，避免造成“点哪里都是同一个星座”的误解。

### 10.5 目标高亮

首页推荐进入星图时，目标高亮应是轻量引导，不是强制教程遮罩。

高亮规则：
- 使用暖色外圈或轻光晕承接首页推荐语气
- 不改变对象原本颜色到无法识别
- 不遮挡中文标签
- 无 target 或未知 target 时安全回退，不显示错误高亮

### 10.6 与 WWT 的关系

WWT 当前保留为底层和专项验证能力。在真实浏览器验证其原生可见渲染稳定之前，StarCanvas 是 V2 的主视觉和主交互层。

因此，V2 星图视觉打磨应优先围绕 StarCanvas 展开，不应通过随机调整 WWT Settings 来解决当前产品体验问题。

### 10.7 推荐承接与 source 视觉规则

首页推荐进入星图时，StarCanvas 必须继承首页的主辅关系，而不是把所有 target 都表现成同等重要。

#### 推荐层级

- 主推荐：强引导。目标必须第一眼可见，并承担“今晚先找它”的行动感。
- 辅推荐：轻定位。目标可以在星图中被定位，但不能抢主推荐权重。
- 无 target：进入默认夜空引导，不显示推荐高亮。
- 未知 target：安全回退，不错误高亮、不制造假入口。

#### 视觉状态优先级

视觉优先级从高到低为：

1. `selectedObject` 选中态
2. `source=primary` 推荐态
3. `source=secondary` 推荐态
4. 普通可点击对象
5. 背景星点

点击对象后进入 `selectedObject` 状态。`selectedObject` 应使用独立选中样式，不复用推荐高亮。若选中对象与推荐目标相同，选中态优先，推荐轻提示消失或降权。若点击其他对象，选中态转移到新对象，推荐提示消失或降权。

#### 高亮强度

- `primary`：明显外圈、更强光晕、可使用慢速呼吸动画，并显示极短画面轻提示“先看这里”。
- `secondary`：小外圈或弱光晕，无动画，不显示“先看这里”。
- 普通可点对象：保持可读中文标签和基础星点亮度，不主动抢第一眼。
- 背景星点：只提供夜空氛围，不显示标签，不参与推荐层级。

#### BottomDrawer 语气

BottomDrawer 引导态应根据 `source` 区分语气：

- `primary`：使用“今晚先找 {target}”，并给出完整行动理由。
- `secondary`：使用“也可以看看 {target}”，并给出简短理由。
- 无 target：使用默认夜空引导。

画面轻提示只负责定位，BottomDrawer 负责解释原因和承接后续动作。二者不应重复堆叠长文案。

## 11. V3 搜索入口与主动探索视觉规范

### 11.1 搜索入口定位

搜索入口 V1 是星图页中的轻量主动探索工具，不是独立工具中心，也不是全屏搜索页。

第一版只放在星图页顶部，负责帮助用户主动锁定一个目标对象，然后让星图把它明确指出来。

### 11.2 搜索框形态

搜索框应保持轻量：
- 不使用厚重后台式输入框
- 不压过星图主舞台
- 使用半透明深色底，与现有顶部状态条融合
- 输入框与结果列表宽度适中，不占满整行
- placeholder 语气偏探索而非后台操作，例如“搜索天体或星座”或“找一颗星或一个星座”

### 11.3 搜索结果列表

第一版搜索结果列表应保持克制：
- 最多显示 5 条结果
- 每条结果只展示中文名与类型标签
- 不发展成复杂筛选器或多 tab 搜索器
- 空结果提示保持极轻，例如“没找到可定位对象”
- 搜索结果点击后默认进入星图定位态，而不是直接跳详情页

### 11.4 `source=search` 视觉规则

`source=search` 的产品语义是“用户主动指定目标”。它不是首页推荐，也不是 related 延续。

视觉优先级从高到低调整为：
1. `selectedObject`
2. `source=search`
3. `source=primary`
4. `source=related`
5. `source=secondary`
6. 普通可点击对象
7. 背景星点

`search` 高亮规则：
- 强于 `primary`，确保用户搜到后第一眼能锁定目标
- 不显示“先看这里”文案
- 不自动等同于 `selectedObject`
- 不遮挡标签，不把对象颜色改到不可识别

### 11.5 搜索后的轻聚焦

搜索命中后，星图不应只是多一个高亮点，还应做轻量聚焦，让目标进入更易观察的位置。

第一版聚焦原则：
- 可以轻量移动视图，让目标靠近更易观察的位置
- 不做强制教程式跳转或粗暴重置视图
- 搜索后依然需要用户主动点击对象，才进入 `selectedObject` 摘要态

### 11.6 BottomDrawer 语气补充

搜索定位态的 BottomDrawer 使用：“正在找 {target}”。

这样与现有语气形成四层区分：
- `primary`：今晚先找 {target}
- `secondary`：也可以看看 {target}
- `related`：接下来可以找 {target}
- `search`：正在找 {target}

## 12. V3 对象池扩容后的星图表现原则

### 12.1 扩展对象层级

对象池扩容后，StarCanvas 不应把所有新增对象都表现成与当前核心对象同等重要。

扩容后的视觉层级建议为：
1. 核心对象：现有主交互对象，标签更清晰、点击承接更完整
2. 扩展可定位对象：数量更多、视觉更轻，但可搜索、可定位、可点击
3. 背景星点：只提供夜空氛围，不承担搜索与承接职责

### 12.2 扩展亮星表现

第一批扩容对象以亮星为主。扩展亮星在画面中的表现应：
- 明显弱于核心对象
- 明显强于纯背景星点
- 可以只对其中一部分显示标签，避免标签密度失控
- 不把整张星图做成密集专业星图或天文软件界面

### 12.3 搜索与扩容对象的关系

对象池扩容后的新增对象，应优先服务搜索与定位体验。

这意味着：
- 搜索结果可以明显变多
- 星图可定位对象可以明显变多
- 但不是所有新增对象都要立即拥有完整详情视觉形态

### 12.4 画面密度边界

扩容后的星图目标是“更像一片可探索天空”，不是“把所有可见点全都铺满”。

因此仍应遵守：
- 标签数量控制
- 核心对象优先级高于扩展对象
- 高亮逻辑先服务目标定位，再考虑画面装饰
- 不把产品做成专业参数面板式星图

## 13. V4 朝向驱动天空视图体验规范

### 13.1 体验定位

朝向驱动模式的目标，不是让整张画布简单旋转，而是让手机端用户获得“站在地球上抬头看天空”的体验。

用户应感受到：
- 手机朝哪，画面就朝哪
- 抬高或放低手机，画面显示的天空区域跟着变化
- 这是一个“天空取景窗口”，不是平面地图拖拽

### 13.2 模式开关

第一版朝向模式不默认强开，应由用户手动开启。

开关要求：
- 放在星图页可发现但不喧宾夺主的位置
- 只在移动端强调其存在
- 普通模式与朝向模式切换应清楚、直接
- 不做复杂设置页或校准中心

### 13.3 权限与失败反馈

朝向模式需要设备方向权限时：
- 请求动作应明确由用户触发
- 失败时保持轻量反馈，不让星图页变成权限错误页
- 回退后继续保留普通星图模式可用
- 不支持设备或桌面端不强行模拟朝向模式

### 13.4 画面行为

朝向模式下，画面的变化应来自“当前视野窗口变化”，而不是简单整体旋转：
- 当前朝向附近的对象进入视野
- 远离当前朝向的对象离开视野或退到边缘
- 搜索/target 高亮仍然成立，但服从当前视野窗口

### 13.5 与现有模式共存

朝向模式仍需与现有星图体验共存：
- 搜索入口继续存在
- `source=primary / related / secondary / search` 语义继续成立
- BottomDrawer 继续承担引导与转交
- 用户点击对象后仍进入 `selectedObject` 摘要态

### 13.6 第一版边界

第一版朝向模式不追求：
- 专业级校准精度
- 复杂罗盘诊断面板
- 多层模式切换系统
- 桌面端一致体验

它的重点是：用户能拿着手机，明显感受到画面在按自己当前朝向看天。
